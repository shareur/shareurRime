# 英文输入说明

[← 返回文档索引](README.md) · [← 返回 README](../README.md)

本仓库有两个英文方案：`easy_en`（主力，词量大 + 整句拆分）与 `melt_eng`（轻量，供中英混输方案调用）。

## 一、方案与词库

| 方案 | 词库来源 | 规模 | 用途 |
| --- | --- | --- | --- |
| `easy_en`（Easy Stream English） | `easy_en.dict.yaml` + `easy_en.main.dict.yaml`（`import_tables` 合成 `user_dicts/`） | 约 25 万常用词 + 2.7 万英文人名 | 独立英文输入、联想补全 |
| `melt_eng`（Easy English Nano） | `melt_eng.dict.yaml`（`import_tables: en_dicts/en_ext` + `en_dicts/en`） | 少量常用词 | 供拼音/五笔方案混输时调用 |

个人词库放在 `user_dicts/`，格式与增删方式见 [05-皮肤字体与自定义词库](05-皮肤字体与自定义词库.md)。

## 二、整句拆分（可选依赖 wordninja）

连写整句（如 `iloveyou`）会被拆成单词候选，候选后标 💡。开关都在 `easy_en.schema.yaml` 的 `easy_en:` 节点：

| 配置项 | 说明 |
| --- | --- |
| `split_sentence` | 整句拆分总开关，默认 `true` |
| `use_wordninja_rs_lua_module` | 用 Rust 版 wordninja 的 Lua 模块（`.so`），三项都未启用时的默认方式 |
| `wordninja_rs_lua_module_path` | 上述模块路径，默认 `/usr/lib/lua/5.4/wordninja.so` |
| `use_wordninja_rs` | 改为调用命令行 `wordninja`（路径见 `wordninja_rs_path`） |
| `use_wordninja_py` | 改为调用 `python -c "import wordninja"`（需自行安装 Python 包） |

行为说明：

- 三种方式都未启用时，按默认的 **Lua 模块**方式尝试加载；
- **本机完全没有 wordninja 时自动降级为「不拆分」**：英文联想补全、Enter 选词等功能照常可用，不会因为缺少可选依赖而报错或吞键（`lua/easy_en.lua` 用 `pcall` 保护）；
- 想彻底关闭拆分，把 `split_sentence` 改为 `false` 即可，无需卸载任何东西。

## 三、Lua 增强组件

都定义在 `lua/easy_en.lua`，由 `easy_en.schema.yaml` / `easy_en.custom.yaml` 挂载：

| 组件 | 挂载位置 | 作用 |
| --- | --- | --- |
| `lua_filter@*easy_en*enhance_filter` | `engine/filters` | 追加整句候选（💡）与生词候选（📝），并把上屏词条写入用户词典；带 ☯ 的候选表示可拆分 |
| `lua_processor@*easy_en*enter_no_space` | `engine/processors` | 回车选词上屏时去掉候选尾部空格（空格选词逻辑不变） |

候选注释含义：

| 注释 | 含义 |
| --- | --- |
| 💡 | 整句拆分结果 |
| 📝 | 由当前输入生成的生词候选（会写入用户词典） |
| ☯ | 可被拆分的原始候选 |

## 四、常见疑问

- **输入英文却被拆成中文拼音候选**：这是 `easy_en` 之外的拼音方案在响应；确认当前方案是 `easy_en`（`` Ctrl+` `` 切方案）。
- **候选里英文单词排序靠后**：由 `lua/reduce_english_filter.lua` 主动降低短英文词位置，可参考该脚本头部注释在自己的方案里调整。
- **Linux 上没有 💡 候选**：多半是没装 wordninja，属正常的降级行为，见上一节。
